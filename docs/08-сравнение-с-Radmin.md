# POSvpn и Radmin VPN: сравнение

Версия: 1.0 от 26.10.2026.
Данные по Radmin VPN — из [research/radmin-features.md](../research/radmin-features.md)
(сбор 26.10.2026, версия 2.1.4951.1). Данные по POSvpn — из [06-ТЗ.md](06-ТЗ.md)
и фактического состояния репозитория.

## 1. Коротко

- Radmin VPN — зрелый бесплатный продукт с настоящим Ethernet-адаптером,
  чатом и 150 узлами. POSvpn сегодня — каркас управления сетью, туннель в
  разработке.
- Radmin сильнее в **совместимости и готовности**: L2, ARP, LAN-игры,
  установка в два клика, 100+ языков.
- POSvpn сильнее в **контроле и встраиваемости**: свой сервер, открытый код,
  своя адресация, API, настраиваемый лимит, отсутствие чужого аккаунта.
- По цене владения POSvpn проигрывает: Radmin бесплатен, POSvpn требует VPS
  и 66–120 часов разработки (см. [07-ТЭО.md](07-ТЭО.md)).
- Выбор зависит от цели: «просто работает сегодня» — Radmin; «свой сервер,
  API и модуль к POSCloud» — POSvpn.

## 4. Технические отличия

### 4.1 L2 против L3 — главное расхождение

Radmin переносит **Ethernet-кадры** через собственный NDIS-драйвер
`RvNetMP60.sys` с `IF_TYPE_ETHERNET_CSMACD`. Поэтому работают ARP, широковещательное
обнаружение, IPX и старые игры.

POSvpn переносит **IP-пакеты** через Wintun. ARP и Ethernet-кадры не проходят.
IP-бродкаст можно размножать в userspace (этап 4), но это не заменяет L2:
часть игр и ПО, которые ищут друг друга через ARP или Ethernet-мультикаст,
не заработает.

Цена перехода на L2: свой NDIS-минпорт с EV-сертификатом и attestation-подписью
Microsoft либо `tap-windows6` под GPLv2. Это отдельный проект по трудоёмкости.

### 4.2 Адресация

| | Radmin VPN | POSvpn |
|---|---|---|
| Диапазон | `26.0.0.0/8` | `10.77.0.0/16` |
| Подсеть сети | не публикуется | `10.77.<N>.0/24`, N = 1…254 |
| Выдача | координатор, конфликты обрабатываются | сервер, первый свободный адрес |
| Конфликты с офисными сетями | возможны: `26/8` занят в части корпоративных схем | маловероятны: `10.77/16` выбран вне типовых подсетей |

### 4.3 Шифрование

| | Radmin VPN | POSvpn |
|---|---|---|
| Заявление | end-to-end 256-bit AES | X25519 + HKDF-SHA256 + ChaCha20-Poly1305 |
| Проверяемость | закрытый код, независимо не проверено | открытый код, тесты в репозитории |
| Что видит сервер | метаданные (заявлено no-log) | метаданные: кто, когда, сколько; содержимое не читает |
| Защита от повтора | не документирована | счётчик nonce + окно приёма |
| Аутентификация узла | пароль сети | токен узла (32 байта) + пароль сети |

### 4.4 Канал и NAT

Radmin: сначала прямой UDP-канал (ENet-подобный), при неудаче — TCP-релей
через инфраструктуру Famatech. Тип канала виден в интерфейсе.

POSvpn MVP: весь трафик через свой хаб. Это всегда работает, включая
симметричный NAT и CGNAT, но добавляет RTT сервера и упирается в его канал.
Прямой P2P (ICE) — этап 4; релей при этом не отключается, а становится резервом.

### 4.5 Лимиты

| | Radmin VPN | POSvpn |
|---|---|---|
| Узлов в сети | 150, увеличить нельзя | 25 по умолчанию, меняется константой на сервере |
| Сетей на пользователя | лимит есть, число не опубликовано | одна на клиент в MVP |
| Трафик | не оговорён | не ограничен, кроме канала VPS |

## 6. Где мы лучше, хуже и так же

**Лучше:**

1. Свой сервер и полный контроль над метаданными.
2. Открытый код и проверяемое шифрование.
3. Адресация `10.77.0.0/16` без конфликтов с `26/8`.
4. API для автоматизации и встраивания в POSCloud.
5. Настраиваемый лимит участников.
6. Русский интерфейс и документация по умолчанию.

**Хуже:**

1. Нет L2: ARP, Ethernet-бродкаст, часть LAN-игр.
2. Нет готового GUI, службы и установщика (этапы 2–3).
3. Лимит 25 узлов против 150.
4. Нет чата, IPv6, прокси, автообновления, 100+ языков.
5. Нужен свой VPS и его обслуживание.
6. SmartScreen предупреждает: нет подписи кода.

**Так же:**

1. Вход по имени сети и паролю, без аккаунта.
2. Роли администратора и пользователя, инвариант «последний админ не уходит».
3. Адрес выдаёт координатор, а не пользователь.
4. Входящие порты из интернета не нужны.
5. Шифрование end-to-end, сервер не читает содержимое.

## 7. Чего у POSvpn не будет

| Функция Radmin | Почему не берём |
|---|---|
| Публичные игровые сети | Другая продуктовая модель, модерация, жалобы |
| Интеграция с Radmin Viewer | Чужой продукт; RDP работает по IP |
| 100+ языков | Достаточно русского, переводы — по спросу |
| Прокси | Редкий сценарий; системный VPN/прокси решает |
| Свой L2-драйвер | Слишком дорого для MVP; решение после этапа 1 |

## 8. Когда что выбирать

| Задача | Выбор |
|---|---|
| Нужно «поставил и работает» сегодня | Radmin VPN |
| Нужны LAN-игры с ARP/Ethernet-обнаружением | Radmin VPN (или L2-трек POSvpn) |
| Нужен свой сервер и контроль данных | POSvpn |
| Нужна автоматизация и API | POSvpn |
| Нужно встроить удалённый доступ в POSCloud | POSvpn |
| Нужно больше 150 узлов | POSvpn (лимит настраивается) |
| Нужны чат, IPv6, прокси, автообновление | Radmin VPN сегодня; POSvpn — этап 5 |

## 9. План догоняния

| Что | Этап | Результат |
|---|---|---|
| Туннель и шифрование | 1 | ping, RDP, SMB между узлами |
| Служба и автозапуск | 2 | работает после перезагрузки без входа в GUI |
| GUI, трей, установщик | 3 | установка за 2 минуты, список участников |
| Прямой канал, IP-бродкаст | 4 | тип канала в UI, часть LAN-игр |
| Права, блокировка, чат, IPv6 | 5 | паритет по функциям, кроме L2 и игровых сетей |

После этапа 4 POSvpn закрывает всё, кроме L2-семантики и публичных игровых
сетей. L2 остаётся осознанным исключением до отдельного решения.
