## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Наименование | POSvpn — виртуальная локальная сеть через интернет |
| Назначение | Замена Radmin VPN для личного и малого офиса: 2–25 узлов |
| Заказчик | Владелец проекта (reznikov73), использует продукт сам |

| Дата начала | 26.10.2026 |

### Термины

| Термин | Значение |
|---|---|
| Сеть | Виртуальная локальная сеть, создаётся по имени и паролю |
| Узел | Компьютер, состоящий в сети; имеет внутренний IP и числовой индекс |
| Карта сети (netmap) | Снимок состава сети, который сервер выдаёт клиенту |
| Хаб | QUIC-релей на сервере, пересылающий кадры между узлами |
| Кадр | Единица данных туннеля: заголовок + зашифрованный IP-пакет |
| Пара ключей | X25519-ключи двух узлов, из которых выводится общий ключ шифрования |
| Индекс узла | Число `uint32` внутри сети, заменяет строковый ID в заголовке кадра |

## 2. Цель и критерии успеха

**Цель.** Два компьютера в разных домашних сетях, без проброса портов и настройки
роутера, видят друг друга по внутренним адресам так же, как в одном офисе.
Вход — по имени сети и паролю, без аккаунта и без администратора.

**Критерии успеха MVP:**

1. `ping` между внутренними адресами работает.
2. RDP и общая папка (SMB) открываются по внутреннему адресу.
3. Пропускная способность через хаб не ниже 50 Мбит/с на канале VPS 1 Гбит/с.
4. Новый участник входит в сеть за минуту, без правки роутера.
5. После перезагрузки Windows туннель поднимается сам.
6. Разрыв связи на 30 секунд не требует перезапуска: канал восстанавливается.

## 3. Границы проекта

### Входит в объём

- Клиент Windows 10/11 x64: служба + GUI + трей.
- Сервер координации и хаб-релей: один бинарник.
- Виртуальный адаптер L3 (Wintun), адрес и маршрут.
- Шифрование «узел ↔ узел», релей через сервер.
- Установщик, автозапуск, журналы.
- P2P-канал и IP-бродкаст — этап 4.

### Не входит в объём

| Что | Почему |
|---|---|
| L2/Ethernet, ARP, LAN-игры | Требует своего NDIS-драйвера с подписью Microsoft; отдельный трек |
| Клиенты macOS/Linux/мобильные | Не нужны для целевого сценария |
| Биллинг, подписки, личный кабинет | Продукт для себя; монетизация — отдельное решение |
| Веб-панель администратора | Управление в GUI и API |
| IPv6, чат, прокси, автообновление, мультиязычность | Этап 5 и позже, по потребности |
| Публичные игровые сети | Модель Radmin, не наша |
| Защита от подмены узла внутри сети | Пароль знают все участники; ограничение зафиксировано в модели угроз |

### 4.3 Туннель

| ID | Требование | Приоритет | Этап |
|---|---|---|---|
| F-3.1 | Виртуальный адаптер Wintun L3, имя `POSvpn`, MTU 1100 (см. п. 7.1) | M | 1 |
| F-3.2 | Адрес узла и маршрут `10.77.0.0/16` назначаются через `winipcfg`; маршрут по умолчанию не меняется | M | 1 |
| F-3.3 | Формат кадра: версия (1 Б), тип (1 Б), dst (4 Б), src (4 Б), epoch (4 Б), counter (8 Б), ciphertext + tag | M | 1 |
| F-3.4 | Типы кадра: 1 — IPv4, 2 — IPv6, 3 — ping, 4 — pong | M | 1 |
| F-3.5 | Ключ пары: `HKDF-SHA256(X25519(priv, peer_pub), salt = network_id, info = "posvpn v1 pair key 1|2")`, 32 байта; два направленных ключа, выбор по индексам | M | 1 |
| F-3.6 | Шифрование ChaCha20-Poly1305; nonce — счётчик, отдельный на каждое направление пары | M | 1 |
| F-3.7 | Защита от повтора: окно приёма, пакеты со старым счётчиком отбрасываются | M | 1 |
| F-3.8 | Хаб принимает QUIC-соединения по токену узла, пересылает кадр по `dst` в пределах одной сети | M | 1 |
| F-3.9 | Хаб подменяет `src` на индекс аутентифицированного отправителя; клиентский `src` не доверяется | M | 1 |
| F-3.10 | `dst = 0` — всем участникам сети, кроме отправителя | S | 1 |
| F-3.11 | Переподключение к хабу с паузой 1, 2, 4… 30 с; heartbeat каждые 30 с | M | 1 |
| F-3.12 | Ошибка `ERROR_GEN_FAILURE` при создании адаптера: `sc delete wintun` и однократное пересоздание | M | 1 |
| F-3.13 | Счётчики: пакеты и байты отправлены/приняты, ошибки шифрования и адаптера — в журнал | S | 2 |
| F-3.14 | IP-бродкаст размножается по пирам (UDP-обнаружение в LAN-играх и софте) | S | 4 |
| F-3.15 | Прямой P2P-канал (ICE), релей остаётся резервом | S | 4 |

## 5. Нефункциональные требования

| ID | Требование | Значение |
|---|---|---|
| N-1.1 | Пропускная способность через хаб | ≥ 50 Мбит/с на VPS 1 Гбит/с; цель 100 Мбит/с |
| N-1.2 | Добавленная задержка | не более 2 × RTT до сервера |
| N-1.3 | Загрузка CPU клиента | ≤ 5% при 10 Мбит/с на 4-ядерном CPU |
| N-1.4 | Время установления туннеля | ≤ 3 с в одной сети, ≤ 10 с за NAT |
| N-2.1 | Доступность сервера | 99% в месяц без SLA; падение не разрушает состояние |
| N-2.2 | Восстановление после сна/смены сети | 5–10 с |
| N-2.3 | Потеря связи с сервером | клиент переподключается бесконечно, без падения |
| N-3.1 | Пароли | PBKDF2-HMAC-SHA256, 600 000 итераций, случайная соль, на сервере только хеш |
| N-3.2 | Токены узлов | 32 случайных байта, на сервере только SHA-256 |
| N-3.3 | Приватный ключ узла | только на клиенте, файл с правами 0600 |

| N-3.6 | Защита API | лимит тела 1 МБ, коды 400/401/403/404/409, без утечки различий «нет сети/неверный пароль» |
