# План работ

Оценки — в «вечерах» по 3–4 часа для одного разработчика. Это не обещание,
а способ сравнить этапы между собой.

## Этап 0. Каркас — сделано

- [x] Модель сети и узла, карта сети, адресация `10.77.0.0/16`.
- [x] Пароли (PBKDF2), токены, ключи X25519.
- [x] API: создать, войти, карта, heartbeat, выйти.
- [x] JSON-хранилище с атомарной записью.
- [x] CLI-клиент, сквозной прогон.
- [x] Тесты: 9 в `engine`, 5 в `posvpn-server`.

**Готово, когда:** `go test ./...` зелёный, «создать → войти → статус»
работает на живом сервере. Выполнено.

## Этап 1. Туннель — 6–8 вечеров

- [ ] Числовые индексы узлов в карте (`index uint32`), версия карты.
- [ ] `wintun.dll` через `//go:embed`, создание адаптера, чтение/запись пакетов.
- [ ] Формат кадра, счётчики nonce, ChaCha20-Poly1305 на пару узлов.
- [ ] QUIC-слушатель на сервере: подключение по токену, приём и пересылка кадров.
- [ ] Клиент: подключение к хабу, отправка/приём, запись в Wintun.
- [ ] Назначение адреса и маршрута `10.77.0.0/16` через `winipcfg`.
- [ ] Обработка Wintun `ERROR_GEN_FAILURE`: `sc delete wintun` + пересоздание.

**Готово, когда:** две машины в разных сетях пингуют друг друга по внутренним
адресам, `iperf3` показывает не меньше 50 Мбит/с, после перезапуска клиента
туннель поднимается сам.

**Риск этапа:** если адаптер не создаётся без UAC — проверить запуск из-под
службы, а не из GUI.

## Этап 2. Служба и автозапуск — 4–5 вечеров

- [ ] `posvpn-service` под SYSTEM: адаптер, туннель, маршруты, DNS.
- [ ] Named pipe между службой и GUI, протокол сообщений.
- [ ] Установка/удаление службы (`sc create`), автозапуск.
- [ ] Восстановление после сна и смены сети.
- [ ] Журналы в `%ProgramData%\POSvpn\logs` с ротацией.

**Готово, когда:** после перезагрузки Windows туннель поднимается без входа
в GUI, а GUI запускается без прав администратора.

## Этап 3. GUI и установщик — 5–7 вечеров

- [ ] Wails v2: окно со списком участников, кнопки «создать» и «войти».
- [ ] Трей: статус, «открыть», «выход», автозапуск.
- [ ] Валидация формы, человеческие ошибки («неверный пароль», «сеть закрыта»).
- [ ] Установщик: служба + GUI + `wintun.msi` + правило брандмауэра.
- [ ] Иконка, версия, ярлыки.

**Готово, когда:** чистая Windows 11, установка за 2 минуты, создание сети и
вход — без консоли и без перезагрузки.

## Этап 4. P2P и бродкаст — 7–10 вечеров

- [ ] STUN: определение внешнего адреса, публикация в heartbeat.
- [ ] Кандидаты в карте сети, `pion/ice`, проверки связности.
- [ ] Прямой канал: кадры идут напрямую, хаб остаётся резервом.
- [ ] Размножение IP-бродкаста по пирам.
- [ ] Метрики: прямой/релей, RTT, потери — в GUI.

**Готово, когда:** в типичной домашней сети канал становится прямым, а при
симметричном NAT автоматически откатывается на релей без разрыва сессии.

## Этап 5. По потребности

Передача прав администратора, блокировка участника, чат, IPv6, несколько
сетей на клиент, автообновление, веб-панель.

## Риски

| Риск | Вероятность | Чем грозит | Что делаем |
|---|---|---|---|
| Wintun не даёт нужный бродкаст | высокая | LAN-игры не работают | Прототип на этапе 1; при провале — решать про tap-windows6 |
| Драйвер ломается после обновлений Windows | средняя | «вчера работало» | Auto-recovery, тест на свежей сборке Win11 |
| Симметричный NAT у всех участников | средняя | всё идёт через хаб | Это норма для MVP; релей — штатный режим |
| Канал VPS — узкое место | средняя | медленно | Лимит 25 узлов, выбор VPS с хорошим каналом, позже P2P |
| SmartScreen и антивирусы | высокая | «не запускается» | Подпись, установщик, меньше подозрительных действий |
| Расползание объёма | высокая | проект не доходит до конца | Жёсткий MVP: сначала ping и RDP, потом всё остальное |

## Что делать прямо сейчас

1. Открыть `e:\Work\VSC\POSvpn` в VS Code, проверить, что `go test ./...`
   проходит в `engine` и `posvpn-server`.
2. Собрать прототип этапа 1 на двух машинах: Wintun + QUIC-хаб + ping.
3. По результату прототипа зафиксировать: остаёмся на L3 или идём в L2.
