а способ сравнить этапы между собой.

## Этап 1. Туннель — 6–8 вечеров (код готов, ждёт проверки на железе)

- [x] Формат кадра: версия, тип, dst, src, epoch, counter; заголовок в AAD.

- [x] Клиент: подключение к хабу, отправка/приём, переподключение 1–30 с.
- [x] Wintun: создание адаптера, чтение/запись пакетов, сессия.
- [x] Назначение адреса и маршрута `10.77.0.0/16` через `winipcfg`.
- [x] Обработка `ERROR_GEN_FAILURE`: `sc delete wintun` + пересоздание.
- [x] Скрипт `tools/fetch-wintun.ps1` с проверкой подписи DLL.
- [x] Проверка на двух машинах через интернет: `ping` — 3/3, 15–24 мс.
- [ ] `iperf3` не меньше 50 Мбит/с и перезапуск клиента.

**Готово, когда:** две машины в разных сетях пингуют друг друга по внутренним
адресам, `iperf3` показывает не меньше 50 Мбит/с, после перезапуска клиента
туннель поднимается сам.

**Сейчас:** две машины в разных сетях пингуют друг друга через интернет
(3/3, 15–24 мс). Осталось измерить пропускную способность (`iperf3`) и
проверить, что после перезапуска клиента туннель поднимается сам.

**Риск этапа:** если адаптер не создаётся без UAC — проверить запуск из-под
службы, а не из GUI.

## Этап 5. По потребности

Передача прав администратора, блокировка участника, чат, IPv6, несколько
сетей на клиент, автообновление, веб-панель.

## Риски

| Риск | Вероятность | Чем грозит | Что делаем |
|---|---|---|---|
| Wintun не даёт нужный бродкаст | высокая | LAN-игры не работают | Прототип на этапе 1; при провале — решать про tap-windows6 |
| Драйвер ломается после обновлений Windows | средняя | «вчера работало» | Auto-recovery, тест на свежей сборке Win11 |
| Симметричный NAT у всех участников | средняя | всё идёт через хаб | Это норма для MVP; релей — штатный режим |
| Канал VPS — узкое место | средняя | медленно | Лимит 25 узлов, выбор VPS с хорошим каналом, позже P2P |
| SmartScreen и антивирусы | высокая | «не запускается» | Подпись, установщик, меньше подозрительных действий |
| Расползание объёма | высокая | проект не доходит до конца | Жёсткий MVP: сначала ping и RDP, потом всё остальное |

## Что делать прямо сейчас

1. Скачать `wintun.dll`: `.\tools\fetch-wintun.ps1` (или `-From <путь>`,
   если сеть медленная).
2. Поднять сервер с хабом: `out\posvpn-server.exe -listen 0.0.0.0:8787 -hub 0.0.0.0:8788`.
3. На двух машинах: `create`/`join`, затем `up -hub <ip сервера>:8788 -pin <отпечаток>`.
4. Проверить `ping` между внутренними адресами и `iperf3`.
5. По результату зафиксировать: остаёмся на L3 или идём в L2.
