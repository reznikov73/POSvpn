# Стек и структура проекта

## 1. Почему Go

Пять причин, каждая проверяема:

1. **Готовые кирпичи.** `golang.zx2c4.com/wintun` (адаптер), `quic-go`
   (транспорт), `pion/ice` + `pion/stun` (NAT traversal), `x/sys/windows/svc`
   (служба), `winipcfg` (маршруты и DNS).
2. **Так сделаны аналоги.** Tailscale, Headscale, NetBird, Netmaker, Nebula —
   Go. Их архитектурные решения переносятся на нашу кодовую базу без смены
   парадигмы.
3. **Один бинарник без зависимостей.** `go build` даёт exe, который не требует
   .NET Runtime или VC++ Redist — важно для установки «в два клика».
4. **Ваш существующий опыт.** `POSCloud` — Go + Wails + Inno Setup + трей.
   Те же приёмы (single instance, config.json рядом с exe, тесты рядом с кодом)
   переносятся напрямую.
5. **Сеть — сильная сторона стандартной библиотеки.** `net/netip`, `crypto/tls`,
   `crypto/ecdh`, `crypto/pbkdf2` (появился в Go 1.24), горутины.

Что не выбрали: Rust — дольше до MVP, другой инструментарий, EasyTier как
референс — 107 тыс. строк; C# — нет mesh-компонентов, Wintun-обвязка пишется
руками; Python — не тот класс задач.

## 3. Структура репозитория

```
POSvpn/
├─ go.work                 # рабочее пространство из трёх модулей
├─ README.md
├─ docs/                   # эта документация
├─ research/               # сырьё разведки (аналоги, Radmin, стек)
├─ engine/                 # общий модуль: протокол, IPAM, секреты
│  ├─ protocol.go
│  ├─ ipam.go
│  ├─ secret.go
│  └─ keys.go
├─ posvpn-server/          # координатор
│  ├─ main.go
│  ├─ api.go
│  ├─ store.go
│  └─ api_test.go
├─ posvpn-client/          # клиент (пока CLI)
│  └─ main.go
└─ installer/              # установщик (этап 3)
```

Почему три модуля, а не один: сервер и клиент собираются в разные бинарники
с разными зависимостями (клиент позже потянет Wails и Wintun, сервер — нет).
`go.work` связывает их локально, `replace` — в `go.mod`.

## 4. Сборка

```powershell
# проверка
go test ./...            # внутри каждого модуля
go vet ./...

# оба бинарника одной командой (то же делает задача VS Code «build: all»)
.\build.ps1

# или по отдельности
go build -o out\posvpn-server.exe .\posvpn-server
go build -o out\posvpn-client.exe .\posvpn-client

# клиент без консольного окна (когда появится GUI)
go build -ldflags "-H windowsgui -s -w" -o out\posvpn-client.exe .\posvpn-client
```

`wintun.dll` кладётся рядом с exe через `//go:embed` и распаковывается при
старте: `LoadLibrary` не умеет грузить DLL из памяти. Установка драйвера —
только через вложенный MSI (`msiexec /i wintun.msi /qn`), это требование
апстрима.

Установщик на этапе 3: Inno Setup 6.7 (как в POSCloud) или WiX v6. Важно:
с 2026 года Inno Setup требует коммерческую лицензию для коммерческого
использования; для личного проекта — бесплатно.

## 5. Настройка VS Code

Расширения: **Go** (golang.go), **Markdown Preview Mermaid Support** (для схем
в этих документах), по желанию **Error Lens**.

`.vscode/settings.json` в проекте:

```json
{
  "go.useLanguageServer": true,
  "go.testFlags": ["-v"],
  "go.lintTool": "vet",
  "editor.formatOnSave": true,
  "[go]": { "editor.defaultFormatter": "golang.go" }
}
```

`.vscode/tasks.json` — сборка и тесты одной командой:

```json
{
  "version": "2.0.0",
  "tasks": [
    { "label": "test: engine", "type": "shell", "command": "go test ./...", "options": { "cwd": "${workspaceFolder}/engine" } },
    { "label": "test: server", "type": "shell", "command": "go test ./...", "options": { "cwd": "${workspaceFolder}/posvpn-server" } },
    { "label": "build: all", "type": "shell", "command": "go build -o out/posvpn-server.exe ./posvpn-server && go build -o out/posvpn-client.exe ./posvpn-client" }
  ]
}
```

Если VS Code не видит модули — откройте папку `POSvpn` целиком (там `go.work`),
а не отдельный подкаталог.

## 6. Подводные камни

1. **Wintun — только L3.** Ни ARP, ни Ethernet-бродкаста. Если LAN-игры
   обязательны — это другой проект по цене (драйвер + подпись).
2. **Wintun ставится только MSI.** Копирование DLL «просто рядом» не работает
   как установка драйвера.
3. **Служба в сессии 0 не показывает UI.** Нужны два процесса и named pipe.
4. **Wintun заморожен с 2022, Windows меняется.** В 2026 зафиксированы
   протухающие записи службы драйвера после обновлений Win11 — нужен
   auto-recovery, а не бесконечный retry.
5. **Inno Setup больше не freeware для коммерции.**
6. **WebView2 нужно доставлять** на Windows 10 (Evergreen bootstrapper), иначе
   белое окно на первом запуске.
7. **MTU.** 1280, не 1500: QUIC + инкапсуляция + PPPoE.
8. **Нет semver у `wireguard-go` и `gvisor`** — только pseudo-version; фиксируйте
   коммит и обновляйте осознанно.
9. **RC-ловушка pion.** Стабильные ветки — ice v4, stun v3, turn v5; v5/v6 в RC
   не трогать.
10. **Подпись.** Без Authenticode SmartScreen предупреждает на каждом запуске;
    репутация набирается объёмом загрузок.

## 7. Что проверить до большого кода

Прототип на ~200 строк: Wintun + чтение/запись пакетов + отправка по
QUIC-дейтаграмме на хаб и обратно. Проверить два сценария на двух машинах:

1. `ping` между внутренними адресами;
2. UDP-бродкаст от одной машины виден на второй.

Если второй сценарий проходит на Wintun — L2-драйвер не нужен, проект
дешевеет в разы. Если нет — решать про `tap-windows6` сразу, не потратив
месяц на обходные пути.
