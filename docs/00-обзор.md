# POSvpn: обзор и три решения, которые определяют проект

Дата: 26 октября 2026. Целевая папка: `e:\Work\VSC\POSvpn`.

## Коротко

POSvpn — это своя замена Radmin VPN: программа, которая собирает компьютеры
из разных сетей в одну виртуальную локальную сеть. Пользователь вводит имя
сети и пароль, получает внутренний IP и видит остальных участников так, будто
они в одном офисе. Роутер настраивать не нужно: трафик проходит через NAT.

Мы делаем не «ещё один VPN-туннель до сервера», а именно **виртуальный LAN**
с адресацией, списком участников, ролями и обходом NAT. Это ближе к Hamachi
и Radmin VPN, чем к классическому «подключиться к офису».

## Три решения

### 1. Язык — Go

| Причина | Факт |
|---|---|
| Все нужные куски уже написаны на Go | `golang.zx2c4.com/wintun`, `wireguard-go`, `quic-go`, `pion/ice`, `pion/stun` |
| На Go написаны прямые аналоги | Tailscale, Headscale, NetBird, Netmaker, Nebula |
| Вы уже в этом стеке | `POSCloud` рядом — Go + Wails + Inno Setup + трей + тесты рядом с кодом |
| Сеть — родная сила языка | `net`, `net/netip`, `crypto/tls`, `crypto/ecdh`, горутины, один статический бинарник |
| Не нужен C-компилятор | в отличие от Fyne; `wintun` и `quic-go` — чистый Go + подписанная DLL |

Альтернативы отпадают по конкретным причинам, а не по вкусу: Rust — дольше до
MVP и другой опыт (EasyTier — 107 тыс. строк), C# — нет готовых mesh-компонентов
и Wintun-обвязки, Python — не тот класс задач для драйверов и сетевого ядра.

### 2. Уровень сети — L3 в MVP, L2 отдельным этапом

Radmin VPN — это **настоящий Ethernet**: собственный NDIS-драйвер
`RvNetMP60.sys`, INF с `IF_TYPE_ETHERNET_CSMACD`, перенос Ethernet-кадров.
Поэтому у него работают ARP, широковещательное обнаружение и старые игры.

На Windows в 2026 году есть только два легальных способа получить L2:
свой NDIS-минпорт (EV-сертификат + attestation-подпись в Microsoft) или
`tap-windows6` (GPLv2, драйвер 2024 года). Оба варианта дороги для MVP на
2–10 узлов.

Поэтому MVP строится на **Wintun** — подписанном L3-адаптере от автора
WireGuard. Следствие, которое надо принять сразу: **ARP, IPX и Ethernet-кадры
не пройдут**, часть LAN-игр не увидит друг друга. IP-бродкаст (UDP discovery)
можно размножать в userspace — это работает для некоторой части игр и софта.

Если LAN-игры окажутся обязательным требованием, это отдельный трек с
`tap-windows6` и своей подписью драйвера. Решение зафиксировано в
[docs/02-функционал.md](02-функционал.md), развилка описана в
[docs/04-стек.md](04-стек.md).

### 3. Данные — свой слой кадров поверх QUIC, а не WireGuard

WireGuard не умеет fan-out: `AllowedIPs` — это карта «префикс → один пир».
Разослать один бродкаст десяти узлам через него нельзя, а именно это отличает
«виртуальную локалку» от VPN-звезды.

Для MVP (2–10 узлов) трафик идёт через хаб — наш же сервер координации:
клиент шифрует IP-пакет ключом, который знает только адресат, и отправляет
дейтаграммой по QUIC; хаб пересылает его по идентификатору узла, не читая
содержимое. Это даёт:

- шифрование «узел ↔ узел» (хаб видит только метаданные);
- бродкаст простым размножением пакета по пирам;
- релей почти бесплатно: хаб и есть релей;
- предсказуемость: не нужно ждать, пока NAT смилостивится.

Прямые P2P-каналы (`pion/ice`) добавляются вторым этапом, когда захочется
убрать нагрузку с хаба; код транспорта при этом не меняется.

Подробно: [docs/03-архитектура.md](03-архитектура.md).

## Что уже сделано в каркасе

- `engine` — модель сети, карта сети, выдача адресов, PBKDF2-пароли, токены,
  ключи X25519. Покрыто тестами.
- `posvpn-server` — HTTP API: создать сеть, войти, получить карту, heartbeat,
  выйти. JSON-хранилище с атомарной записью. Тесты: 5 сценариев, включая
  перезапуск и «последний админ не может уйти».
- `posvpn-client` — CLI: `create`, `join`, `status`. Сквозной прогон на живом
  сервере проходит.

## Чего в каркасе ещё нет

Виртуального адаптера, туннеля, службы Windows, трея и GUI, установщика,
бродкаста, P2P. Это этапы 1–4 в [docs/05-план.md](05-план.md).

## Допущения, на которых построен план

1. Цель — рабочий инструмент для себя и небольшой группы, а не продукт с
   биллингом: 2–10 узлов, один сервер координации.
2. Windows 10/11 x64 — единственная платформа первого этапа.
3. Сервер разворачивается на VPS с публичным IP; TLS-терминация — на нём же.
4. LAN-игры не входят в MVP; если войдут — потребуется L2-драйвер и подпись.
