# POSvpn: прокси — интернет через другой узел

Версия: 1.0 от 27.10.2026. Проверено на сборке 0.9.1.

Узел сети может отдавать свой интернет остальным участникам по SOCKS5.
Ниже — как включить прокси на шлюзе, как настроить приложения на остальных
узлах и как убедиться, что трафик идёт через шлюз.

## 1. Когда это нужно

- На вашем компьютере нет прямого интернета (или он с ограничениями),
  а у другого узла сети интернет есть.
- Нужно, чтобы конкретные приложения (браузер, Telegram, git) выходили
  в сеть с адреса другого узла.

Это не «весь VPN через шлюз»: маршруты на клиенте не меняются. В прокси идёт
только то, что вы сами направили, — ошибиться и потерять локальную сеть
нельзя. Прокси работает по TCP (`CONNECT`); UDP и BIND не поддерживаются.

## 2. Кто что делает

| Роль | Что настроить |
|---|---|
| Узел-шлюз — у него есть интернет | включить прокси в настройках клиента |
| Остальные узлы | вписать адрес шлюза в приложения как SOCKS5-прокси |

Шлюз должен быть включён и подключён к сети: прокси живёт ровно столько же,
сколько туннель.

## 3. Включение на узле-шлюзе

1. Открыть окно POSvpn → «Настройки».
2. Раздел «Прокси» → галочка «Выход в интернет через этот узел».
3. Порт оставить `1080`. Если он занят другой программой — указать свой
   (1024–65535), его придётся вписать и на клиентах.
4. Если в сети есть не только свои — задать логин и пароль. Пароль без
   логина не сохраняется: без логина прокси работает без авторизации.
5. «Сохранить». Служба применит настройки, туннель переподключится,
   прокси поднимется вместе с ним.

В главном окне появится строка с адресом:

```
Прокси: 10.77.1.1:1080
```

Пока туннель не поднят, там будет пометка «(включится с туннелем)». В окне
настроек рядом с адресом есть кнопка «Копировать» — удобно переслать адрес
на другой узел.

Что происходит внутри: порт слушается на всех интерфейсах, но соединения
принимаются только из подсети вашей сети (`10.77.<N>.0/24`). С локальной
сети и с физического адаптера порт недоступен, отдельное правило
брандмауэра не нужно.

Без окна, для скриптов: в `client.json` задать `"proxy_enabled": true`
и `"proxy_port": 1080`, затем запустить `posvpn-client.exe up`.

## 4. Настройка на остальных узлах

Адрес шлюза — `10.77.<N>.1` (номер подсети вашей сети) и порт из настроек
шлюза. Тип прокси — **SOCKS5**, не HTTP. DNS лучше отдавать шлюзу
(`socks5h`), тогда имена разрешает он.

### Браузер

Chrome, Edge и Яндекс.Браузер берут системные настройки Windows:

Параметры → Сеть и Интернет → Прокси → «Использовать прокси-сервер» →
«Дополнительно» → SOCKS: `10.77.1.1`, порт `1080`.

Firefox настраивается отдельно: Настройки → Сеть → Прокси → «Ручная
настройка» → SOCKS-узел `10.77.1.1:1080`, «SOCKS v5», галочка
«Проксировать DNS при использовании SOCKS v5».

Системный прокси затрагивает все приложения, которые его слушают. Если
шлюз пропал, браузер перестанет открывать сайты — верните «Без прокси».

### Telegram Desktop

Настройки → Продвинутые настройки → Тип соединения → SOCKS5 → сервер
`10.77.1.1`, порт `1080`, логин и пароль, если заданы на шлюзе.
Звонки через такой прокси не пойдут: для них нужен UDP.

### Командная строка

```powershell
# проверить, что видит интернет адрес шлюза, а не ваш
curl.exe -x socks5h://10.77.1.1:1080 https://ifconfig.me

# git
git config --global http.proxy  socks5h://10.77.1.1:1080
git config --global https.proxy socks5h://10.77.1.1:1080
# отключить
git config --global --unset http.proxy
git config --global --unset https.proxy
```

## 5. Как убедиться, что всё работает

На шлюзе:

- в главном окне строка «Прокси: …» без пометки;
- в журнале `data\logs\service.log` строка
  `прокси включён: 10.77.1.1:1080 (только из 10.77.1.0/24)`;
- порт слушается:

```powershell
Get-NetTCPConnection -LocalPort 1080 | Select-Object LocalAddress,State
```

На клиенте: запрос через прокси возвращает страницу, а в журнале шлюза
появляются строки вида `прокси: 10.77.1.2:54321 → example.com:443`.

## 6. Ограничения

- Только TCP: игры, видеозвонки, часть торрентов и QUIC-трафик через прокси
  не пойдут. Браузер обычно сам откатывается на TCP.
- Прокси работает, пока клиент подключён к сети. Отключились — порт закрыт.
- Скорость ограничена каналом шлюза и его загрузкой.
- Без логина и пароля любой участник сети может выходить в интернет через
  вас, и его запросы будут выглядеть как ваши. В общей сети включайте
  авторизацию.
- Прокси не заменяет шифрование: HTTP остаётся HTTP. До шлюза трафик идёт
  внутри туннеля, дальше — как обычный запрос шлюза.

## 7. Выключение

Настройки → снять галочку «Выход в интернет через этот узел» → «Сохранить».
Туннель переподключится, порт закроется. На клиентах уберите прокси
из приложений, иначе они перестанут выходить в сеть.

## 8. Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| В главном окне нет строки «Прокси» | галочка не включена | включить в настройках и сохранить |
| «(включится с туннелем)», порт закрыт | туннель не поднят | подключиться к сети |
| С другого узла «connection refused» или таймаут | шлюз офлайн, прокси выключен, другой порт | проверить шлюз, порт и адрес |
| Приложение просит авторизацию или отказывается | на шлюзе задан логин и пароль | вписать пару в приложении |
| Прокси отвечает, но сайты не открываются | у шлюза нет интернета или не работает DNS | на шлюзе проверить `curl.exe https://example.com` |
| Часть сайтов не открывается | приложение не умеет SOCKS5 или требует HTTP-прокси | использовать SOCKS5 и `socks5h` |
| При включении «порт занят» | 1080 занят другой программой | сменить порт на шлюзе и на клиентах |
| Медленно | загружен канал шлюза | выбрать другой узел-шлюз |

## 9. Как проверялось на двух узлах

Сеть `proxy-test`, два узла: шлюз `10.77.1.1` (прокси включён, порт 1081)
и второй узел `10.77.1.2`.

```powershell
# на втором узле
curl.exe --interface 10.77.1.2 -x socks5h://10.77.1.1:1081 https://example.com
```

Результат: `200 OK`, в журнале шлюза — `прокси: 10.77.1.2:<порт> → example.com:443`.
Источники вне подсети (адреса физических адаптеров) получают отказ:
`прокси: отказ источнику 192.168.5.81 (не из сети)`. После остановки шлюза
запрос со второго узла не проходит (таймаут) — обмен идёт именно через
узел-шлюз.

## 10. Пример: два ПК — браузер через шлюз, ИИ-агент напрямую

Задача: второй ПК ходит в интернет через первый, но не весь. Браузер должен
выходить с адреса первого ПК (белый IP, нужная страна), а ИИ-агент — через
собственное подключение второго ПК: быстрее и без лишнего узла в цепочке.

```
      интернет A                          интернет B
           │                                   │
      ┌────┴─────┐       туннель         ┌─────┴────┐
      │   PC-1   │ ══ 10.77.1.0/24 ═════ │   PC-2   │
      │  шлюз    │                        │  клиент  │
      │ 10.77.1.1│                        │ 10.77.1.2│
      └──────────┘                        └────┬─────┘
                                         ┌────┴─────┐
                                         │ браузер  │ → через PC-1
                                         │ ИИ-агент │ → напрямую, B
                                         └──────────┘
```

Почему это работает без маршрутов: POSvpn не трогает маршрут по умолчанию — он только добавляет маршрут к 10.77.0.0/16.
В туннель уходят только адреса `10.77.x`. Всё остальное на PC-2 идёт по
обычному маршруту — через интернет B. А браузер попадает на PC-1 потому,
что вы сами дали ему SOCKS5-прокси. Приложение, которому прокси не указан,
ходит напрямую.

### Шаг 1. PC-1 — включить шлюз

1. Войти в сеть и подключиться.
2. Настройки → «Прокси» → «Выход в интернет через этот узел», порт `1080`.
   Если сеть не только для своих — логин и пароль.
3. «Сохранить», дождаться строки «Прокси: 10.77.1.1:1080» в главном окне.
4. Проверить журнал `data\logs\service.log`: `прокси включён: 10.77.1.1:1080`.

PC-1 должен быть включён и подключён, пока браузер PC-2 ходит через него.

### Шаг 2. PC-2 — войти в сеть

1. Установить клиент, войти в ту же сеть (имя сети и пароль), подключиться.
2. В главном окне адрес `10.77.1.2`, в списке узлов — `10.77.1.1`.
3. Проверить связь: `ping 10.77.1.1` — четыре ответа.

Интернет B при этом остаётся рабочим: туннель его не отбирает.

### Шаг 3. Браузер на PC-2 — только он идёт через PC-1

Вариант А, отдельный ярлык (Chrome/Edge). Системные настройки не меняются,
остальные приложения прокси не видят:

```bat
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --proxy-server="socks5://10.77.1.1:1080" --user-data-dir="C:\posvpn\browser-profile"
```

Для Chrome путь `C:\Program Files\Google\Chrome\Application\chrome.exe`,
флаги те же. Отдельный `--user-data-dir` держит эту копию браузера в своём
профиле: настройки не смешаются с обычным окном.

Проверено в этом репозитории: Edge с таким флагом реально идёт через SOCKS5
и передаёт прокси **имя сайта** (`ATYP=3` в запросе `CONNECT`), то есть DNS
разрешает шлюз, а не PC-2.

Вариант Б, Firefox с отдельным профилем:

```bat
firefox.exe -P posvpn --no-remote
```

В этом профиле: Настройки → Сеть → Прокси → «Ручная настройка» →
SOCKS-узел `10.77.1.1`, порт `1080`, «SOCKS v5», галочка
«Проксировать DNS при использовании SOCKS v5».

Вариант В, PAC-файл — если через шлюз должны идти только отдельные сайты:

```js
function FindProxyForURL(url, host) {
  if (shExpMatch(host, "*.example.com")) return "SOCKS5 10.77.1.1:1080";
  return "DIRECT";
}
```

Запуск: `msedge.exe --proxy-pac-url="file:///C:/posvpn/proxy.pac"`.

### Шаг 4. ИИ-агент на PC-2 — ничего не настраивать

Агент (CLI вроде `claude`, `codex`, `aider`, IDE-плагин, локальный клиент)
ходит по HTTPS через системный стек. Пока системный прокси выключен и в
окружении нет `*_PROXY`, он идёт через интернет B, как обычная программа.

Проверить, что ничего не перехватывает:

```powershell
# системный прокси должен быть выключен
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' |
  Select-Object ProxyEnable, ProxyServer

# переменные прокси в текущей сессии и в профиле пользователя
Get-ChildItem Env: | Where-Object Name -match 'PROXY'
[Environment]::GetEnvironmentVariable('HTTPS_PROXY','User')
[Environment]::GetEnvironmentVariable('HTTPS_PROXY','Machine')
```

Пустой вывод у переменных — то, что нужно. Если что-то задано — убрать:

```powershell
Remove-Item Env:HTTP_PROXY, Env:HTTPS_PROXY, Env:ALL_PROXY -ErrorAction SilentlyContinue
[Environment]::SetEnvironmentVariable('HTTPS_PROXY', $null, 'User')
```

### Шаг 5. Проверка, что разделение работает

| Где | Что сделать | Ожидаемый результат |
|---|---|---|
| Браузер PC-2 (ярлык из шага 3) | открыть `https://ifconfig.me` | внешний IP интернета A — то есть адрес PC-1 |
| Терминал на PC-2 | `curl.exe https://ifconfig.me` | внешний IP интернета B |
| Журнал PC-1 | `data\logs\service.log` | строки `прокси: 10.77.1.2:… → …` по сайтам из браузера |

Если адреса совпали — либо у PC-1 и PC-2 один и тот же провайдер и один
внешний IP (тогда проверять нечего), либо браузер не подхватил прокси:
запустите его ярлыком из шага 3, а не обычным.

Браузер гоняет через прокси и служебные запросы (`edge.microsoft.com`,
`config.edge.skype.com`, проверка SmartScreen). Это нормально: на шлюзе они
будут видны в журнале. Если это нежелательно — отдельный профиль и отключение
фоновых сервисов в нём.

### Шаг 6. Обратный вариант: агент через шлюз, браузер напрямую

Тот же приём, только прокси получает агент. Ярлык или скрипт запуска:

```bat
@echo off
rem agent-proxy.cmd — запуск агента через шлюз POSvpn
set HTTPS_PROXY=socks5h://10.77.1.1:1080
set HTTP_PROXY=socks5h://10.77.1.1:1080
set NO_PROXY=10.77.1.1,127.0.0.1,localhost
"C:\Tools\agent\agent.exe" %*
```

В PowerShell:

```powershell
$env:HTTPS_PROXY = 'socks5h://10.77.1.1:1080'
$env:HTTP_PROXY  = 'socks5h://10.77.1.1:1080'
claude
```

`socks5h` — чтобы имена разрешал шлюз. Учтите: не все агенты читают эти
переменные (часть Node-инструментов смотрит только `ALL_PROXY` или свои
настройки). Проверять надо изнутри агента: попросить его показать
`https://ifconfig.me` или посмотреть журнал шлюза.

### Шаг 7. Что может пойти не так

| Симптом | Причина | Решение |
|---|---|---|
| Браузер показывает IP PC-2 | ярлык без флага, профиль со старыми настройками | запускать ярлыком из шага 3, проверить `--user-data-dir` |
| Сайты не открываются, IP верный | DNS или QUIC | включить удалённый DNS (для Firefox — галочка), добавить `--disable-quic` |
| Браузер просит логин и пароль | на шлюзе включена авторизация | ввести пару; в Firefox — в настройках прокси |
| Агент внезапно пошёл через шлюз | включён системный прокси или заданы `*_PROXY` | выключить системный прокси, убрать переменные |
| Ничего не работает на PC-2 | нет туннеля или шлюз офлайн | проверить `ping 10.77.1.1`, строку «Прокси» на PC-1 |
| У PC-2 нет своего интернета | разделять нечего | пускать через шлюз и агента: шаг 6 |
## 11. Где журналы

| Файл | Что пишет |
|---|---|
| `data\logs\service.log` | служба клиента: туннель, прокси, отказы источникам |
| `data\logs\client.log` | клиент, запущенный из командной строки |
| `data\logs\server.log` | координатор и хаб |

Каталог `data` лежит рядом с программой (портативная установка) либо
в `%ProgramData%\POSvpn`.
