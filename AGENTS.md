# Правила работы над POSvpn

Файл для людей и ИИ-агентов. Проект ведётся разными пользователями и в разных
сессиях, поэтому договорённости живут в репозитории, а не в переписке.

## 1. Язык

- Документация, комментарии в коде, сообщения коммитов и интерфейс — по-русски.
- Имена пакетов, типов, функций и полей JSON — по-английски.
- Термины: «узел», «сеть», «карта сети», «хаб», «кадр» — как в
  [docs/06-ТЗ.md](docs/06-ТЗ.md).

## 2. Источник правды

1. `docs/` — единственный источник правды. Решение, которого нет в `docs/`,
   не считается принятым.
2. Архитектурные решения (L3, QUIC, свой кадр, адресация `10.77/16`) меняются
   только с записью в [docs/03-архитектура.md](docs/03-архитектура.md) и
   объяснением причины.
3. Новые зависимости фиксируются с версией и обоснованием в
   [docs/04-стек.md](docs/04-стек.md).
4. Требования и их статус — в [docs/06-ТЗ.md](docs/06-ТЗ.md); этапы — в
   [docs/05-план.md](docs/05-план.md).

## 3. Начало сессии

```powershell
git log --oneline -10
git status
go test ./...        # в engine и posvpn-server
```

Затем прочитать `README.md`, `docs/05-план.md`, `docs/06-ТЗ.md`.

## 4. Конец сессии

Коммит должен содержать код, тест и обновлённые документы:

```powershell
.\build.ps1
git add -A
git commit -m "туннель: кадры и QUIC-хаб"
```

Сообщение: `<область>: <результат>`, на русском, без «fix», «update», «wip».

## 5. Проверки

| Что | Команда |
|---|---|
| Тесты общих типов | `cd engine; go test ./...` |
| Тесты сервера | `cd posvpn-server; go test ./...` |
| Сборка обоих exe | `.\build.ps1` |
| Релиз и пуш | `.\release.ps1 "сообщение"` |

`go test ./...` должен быть зелёным до коммита. Новая функция — с тестом.

## 6. Запреты

- Не коммитить секреты: `client.json`, `server.json`, `*.log`, приватные ключи.
- Не менять `10.77.0.0/16` и формат кадра без записи в `docs/03`.
- Не добавлять зависимости «на всякий случай»: только под конкретное требование.
- Не обещать в документах то, чего нет в коде: статус требования — только
  «сделано», «в работе», «план».

## 7. Структура

| Путь | Что это |
|---|---|
| `engine/` | Общие типы, адресация, секреты, ключи, тесты |
| `posvpn-server/` | Координатор: API, хранилище, хаб (этап 1) |
| `posvpn-client/` | Клиент: CLI сейчас, служба и GUI — этапы 2–3 |
| `installer/` | Inno Setup, версия продукта |
| `docs/` | Документация: обзор, аналоги, функционал, архитектура, стек, план, ТЗ, ТЭО, сравнение |
| `research/` | Сырьё разведки, не переписывается задним числом |

## 8. Definition of done

1. Требование из ТЗ выполнено и проверено вручную или тестом.
2. `go test ./...` зелёный, `.\build.ps1` собирается.
3. Документы обновлены: статус в `README.md`, отметки в `docs/05-план.md`,
   при необходимости — ТЗ и архитектура.
4. Коммит в `main` с понятным сообщением.
